# GPS and dispatch performance

The business planning profile is 10,000 orders/day. A hypothetical 5,000 active pilots reporting every 5 seconds implies 1,000 updates/second before subscriptions; it is a workload target, not measured capacity. A local single-process smoke sent 30 sequential authenticated GPS requests to PostgreSQL: 89.03 updates/second, p50 11.13 ms and p95 13.32 ms in the recorded run. Two concurrent pilot offer requests for one task resolved in 63.15 ms. See the JSON evidence beside this file. This is not a sustained or multi-pilot load test. No 100/500/2,000/5,000 pilot profile, WebSocket fan-out benchmark, or production-like Redis/PostGIS stack was available. The observed values are machine- and test-harness-specific and do not establish capacity or freshness SLOs. Capture those metrics in a provisioned environment before production sizing.
