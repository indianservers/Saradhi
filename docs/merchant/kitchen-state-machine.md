# Kitchen task state machine

```text
pending ──start──> in_progress ──complete──> completed
                       │                         (terminal)
                       └──pause──> paused ──resume──> in_progress
```

Only these transitions are accepted. Every mutation carries `expected_version`; stale devices receive `version_conflict`. Retrying the current state is idempotent and returns the current task. Completed tasks cannot be reopened through this endpoint.

Tasks can start only while their merchant order is `preparing`. A task with unfinished prerequisite tasks returns `task_blocked`. The station row is locked before counting active work, serializing capacity checks for devices on the same station. Tasks cannot be assigned after start, to inactive stations, or between prep/packing station types.

Order readiness is a separate merchant transition. It requires at least one initialized task and all tasks completed. Countdown expiry never changes a task or order state. Audit records capture task state/reassignment actions with actor identity, branch organization, version, and state change. The database dependency table forbids self-dependencies and duplicate edges; there is not yet a general graph editor or cycle validator because dependencies are generated by the service.
