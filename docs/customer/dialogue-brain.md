# Contextual TensorFlow dialogue brain

The new candidate consumes conversation memory plus the current message and generates a
seven-field dialogue plan:

```text
action|dish|quantity|budget|diet|sort|next_step
search|chicken biryani|4|300|vegetarian|price|show_matches
```

The primary candidate instruction-tunes the pretrained FLAN-T5 encoder-decoder in TensorFlow.
It preserves the encoder and earlier decoder layers and trains the planning decoder layers
against full conversation-state prompts. A separate character encoder-decoder provides a
domain-specific fallback candidate. The output contains tool arguments and the next dialogue step. It can carry a dish
forward while changing quantity/budget, choose a dietary/price filter, change the dish, request
missing information or explain a workflow. The existing pretrained FLAN-T5 model supplies a
search-phrase fallback. This is a bounded ordering assistant; broad open-domain reasoning and
human-level understanding are not claimed.

## New data

`brain-commands.jsonl` is generated by `brain_data.py` and currently contains 5,221
state/message examples and 3,403 distinct utterances. The fifth expansion adds 120
distinct training utterances relative to version 4. There are 4,192 training examples
and 1,029 development examples, including contexts sharing an utterance but requiring
different results. Version 1 used 1,583 examples with 249 new training utterances.
All examples are synthetic. Customer conversations, tokens and precise GPS data are excluded.

The frozen 20-conversation audit in `audit_brain.py` and fresh 12-conversation audit
in `audit_brain_v2.py` are excluded from training and development examples. Tests assert this separation. Evaluation reports both raw structured
accuracy and bounded, validated-plan accuracy; failed/low-confidence outputs can abstain.
Development performance must not be presented as production accuracy.

## Conversation memory and grounding

`brain_memory` persists dish, quantity, budget, dietary filter, sort and stage in each chat's
SQLite session. The model receives these fields; preparation notes, account tokens, GPS and
customer identity are not part of that memory prompt. Explicit navigation buttons remain
available when inference fails. Oversized prompts use the existing fallback instead of a
silently truncated dialogue plan.

Generated plans pass through a Pydantic schema and numeric consistency checks. New menu names
are grounded in current merchant catalogs. The model cannot invent a menu price, confirm
availability, declare an allergen safe or decide whether a payment succeeded. Merchant catalog,
coverage, quote and payment APIs retain authority over those facts.

Read-only navigation/discovery can follow a valid plan. Cart changes need reviewable buttons;
ordering requires the existing quote-bound confirmation; payments require merchant acceptance
and provider verification. A plan proposing confirmation opens checkout for review.

## Training and activation

```powershell
./.local/telegram-ai-venv/Scripts/python.exe -m backend.integrations.telegram.train_transformer_brain
./.local/telegram-ai-venv/Scripts/python.exe -m backend.integrations.telegram.evaluate_transformer_brain
# Character-level fallback candidate:
./.local/telegram-ai-venv/Scripts/python.exe -m backend.integrations.telegram.train_brain
# Resume an existing checkpoint while preserving optimizer state:
./.local/telegram-ai-venv/Scripts/python.exe -m backend.integrations.telegram.train_brain --resume
./.local/telegram-ai-venv/Scripts/python.exe -m backend.integrations.telegram.evaluate_brain
```

Both trainers encode the full `input` field, including memory. The pretrained candidate uses
112 input tokens and 48 output tokens for five instruction-tuning epochs. The character
candidate uses 144 input characters and 64 output characters, covering every example in the
new corpus with padding margin; it completes 45 total epochs. Progress is written after each
epoch. The character candidate's development complete-plan score was 71.0%, contextual-case
score 58.6% and unseen-conversation score 40%; these results motivated the pretrained model.

Candidate weights, progress, development results, independent audit and deployment manifest
live under ignored `.local/models/quickbuddy-transformer-brain/` and
`.local/models/quickbuddy-brain/`. The previous deployed model remains
separate under `.local/models/quickbuddy-nlp/`. Activation verifies a SHA-256 manifest against
the evaluated weight file. The control page's Reload evaluated dialogue brain button performs
a locked model swap; a missing/mismatched manifest retains the existing model.

NLP interpretation traces on the control page show the generated plan and confidence so
multi-turn behavior can be inspected during testing. These traces are not training examples.

## Evaluated pretrained model

The five-epoch TensorFlow FLAN-T5 run achieved 93.55% complete-plan exact match
on 310 held-out synthetic examples and 100% on their contextual subset. On the
separate 20-example unfamiliar-phrasing audit it achieved 60% exact match and
10% abstention. The small synthetic evaluation does not establish general language
understanding. Confidence and grounding checks remain mandatory; merchant data,
prices, availability, order submission and payment verification stay in application code.

## Version 2 corpus expansion

The second expansion adds 672 distinct training utterances relative to version 1,
and reserves another 80 new utterances for development. The full corpus has 2,879
state/message examples: 2,353 train and 526 development. There are 1,835 distinct
utterances overall. No full model input occurs in both splits, and the frozen
independent conversation audit remains excluded from training.

New examples cover English and Romanized Telugu/Hindi discovery, spending limits,
headcount corrections and budget corrections while preserving previous dish,
quantity and sorting context. The examples remain synthetic. This expansion does
not add an unrestricted agent, native-script fluency, or new commerce capabilities.

To train a separate candidate without overwriting the running model, set
`QUICKBUDDY_TRAIN_OUTPUT` to `.local/models/quickbuddy-transformer-brain-v2`
(an absolute path is recommended), then run the training and evaluation modules
listed above. Only evaluated weights should replace the active model.

### Version 2 evaluation and activation

Five TensorFlow epochs finished with training loss 0.03381. Complete-plan exact
match was 95.82% on 526 synthetic development cases, including 100% on the added
216 cases and 92.90% on the original 310 (version 1: 93.55%). Contextual development
cases scored 100%. The frozen 20-case audit improved from 60% to 70%, with 10%
abstention. The fresh 12-case composition audit scored 50%, with 8.33% abstention.
These small synthetic evaluations show continuing limits on unfamiliar phrasing.

The evaluated candidate is activated in the standard transformer brain directory;
previous weights are preserved at `.local/models/quickbuddy-transformer-brain-before-500-expansion/`.
A subsequent application grounding check requires a proposed new dish to have
literal, localized or close spelling evidence in the message; otherwise it asks
which dish the customer means. The reported audit figures above were measured
before this additional check, and have not been increased to claim its benefits.
Full development/audit outputs and dataset fingerprint are saved with the weights.

## Version 3: compound edits and continued training

This expansion adds 811 distinct new training utterances and 175 new development
utterances beyond version 2. It includes joint portion/budget updates, dish
replacement while retaining other selections, contextual follow-ups, navigation,
and clarification requests. Existing examples remain in training as replay data.
The frozen audits stay out of the corpus.

Version 3 continues from the deployed version 2 TensorFlow weights for two epochs
at learning rate 0.0001, training the last three decoder blocks as before. This is
continued weight training with a fresh optimizer, not resumption of old optimizer
state. Padding is sized to observed training lengths (64 input and 24 target
tokens); serving limits remain 112/48. Assertions prevent silent truncation.

Set `QUICKBUDDY_TRAIN_OUTPUT` to the candidate folder, `QUICKBUDDY_TRAIN_SOURCE`
to the initial checkpoint folder, `QUICKBUDDY_TRAIN_EPOCHS` to `2`, and
`QUICKBUDDY_TRAIN_RATE` to `0.0001` before running the trainer. Source weights and
dataset hashes are recorded with the candidate. Scores are recorded after evaluation.

### First version 3 candidate: held back

The first continued-training candidate reached 93.01% complete-plan development
accuracy (new cases 93.45%, previous version 2 cases 92.78%). Its frozen audit
fell to 60%, versus a 75% freshly measured runtime baseline. The composition audit
remained 50%. It was not activated. Many failures were malformed plan delimiters
or navigation mistakes, rather than errors on the compound quantity/budget cases.

A second candidate resets to the same deployed source weights, lowers learning
rate to 0.00005 and replays non-search examples five times using
`QUICKBUDDY_ACTION_WEIGHT=5`. This means 4,268 effective fit examples per epoch,
but still only 3,388 unique training contexts and 811 new training utterances.
The corpus and frozen audits are unchanged. Candidate folders preserve both runs.

### Activated version 3 results

The balanced candidate completed two epochs with replay loss 0.05928. It scored
95.88% complete-plan exact match across 801 synthetic development cases; previous
version 2 cases improved from 95.82% to 97.34%, while the new 275 cases scored
93.09%. Contextual development cases scored 97.22%.

On the frozen audit it matched the current runtime baseline at 75% (15/20), with
5% abstention. The composition audit improved from 50% to 58.33% (7/12). These
small audits still show significant limitations with unfamiliar phrasing; the
assistant remains a bounded generative ordering planner, not a general reasoning
agent. Merchant facts and writes remain controlled by application logic.

The balanced candidate is activated in the standard transformer model directory.
Previous deployed weights are backed up in
`.local/models/quickbuddy-transformer-brain-before-v3-expansion/`. The first,
regressed candidate remains separate and was never activated. All 19 focused
application tests and lint checks passed.

## Version 4: joint dietary and order-preference changes

This expansion adds 324 distinct new training utterances and 108 held-out new
utterances beyond version 3. Each combines a vegetarian/vegan preference with dish,
portion and budget arguments while retaining any saved price sorting. Dietary
matching remains based on merchant labels; the model cannot establish allergen
safety or claim that a dish is suitable without merchant data.

The candidate continues from the deployed version 3 checkpoint for one epoch at
learning rate 0.00002, with fivefold non-search replay. There are 3,712 unique
training contexts and 4,592 effective fit examples with replay. Padding is 64 input
and 27 target tokens, within serving limits. The unchanged frozen audits and
previous 801 development cases are kept separate from training. Results follow
once evaluation finishes; training alone does not establish general understanding.

### Activated version 4 evaluation

The candidate completed one epoch with replay loss 0.05752. Complete-plan exact
match was 96.37% across 909 synthetic development cases; the previous 801 cases
remained at 95.88%, and all 108 new cases were correct. Contextual development
cases scored 97.66%. The frozen 20-case audit improved from 75% to 80%, with no
abstention; the 12-case composition audit stayed at 58.33%. These small tests do
not establish broad real-world language understanding.

The evaluated candidate is activated in the standard transformer directory.
Previous weights are preserved in
`.local/models/quickbuddy-transformer-brain-before-v4-expansion/`. Hash verification
and regression checks passed before activation. All 20 focused application tests
and lint checks passed. The control page exposes the 324 newly trained commands.

A live simulator check exposed an older query-concatenation path restoring meat
terms after a vegetarian plan. Context concatenation now applies only to legacy
queries; a full neural plan supplies its own complete query. The regression test
and all 21 focused application tests pass.

## Version 5: saved weights and memory-preserving budget changes

tokenizer files, metadata and a SHA-256 weights manifest. The weights occupy
439,831,384 bytes. This is a local export, not an off-device backup.

Version 5 adds 120 distinct new training utterances and 30 new development
utterances. Each appears with four different memory states, requiring different
answers for retained diet, quantity and sorting preferences. This gives 480 new
training contexts and 120 new development contexts. No audit inputs enter training.

The candidate continues from the exported deployed checkpoint for one epoch at
learning rate 0.00002, retaining fivefold non-search replay. There are 4,192 unique
training contexts and 5,072 effective fit examples. Maximum training lengths are
67 input and 27 target tokens, within serving limits. Evaluation follows training;
new trained weights are exported separately after completion.

### Saved version 5 results: not activated

Training completed with replay loss 0.05914. Development complete-plan exact
match was 97.08% over 1,029 cases; all 120 new context cases were correct, and
previous version 4 cases improved from 96.37% to 96.70%. Contextual cases scored
98.26%. The composition audit improved from 58.33% to 66.67%, but the frozen audit
fell from 80% to 75%, with 5% abstention. The running bot therefore keeps version 4.

New trained weights are saved separately at
`.local/exports/telegram-brain-v5-20261027/tf_model.h5` (439,831,384 bytes), alongside
config, tokenizer, training metadata, evaluation/audit reports and
`weights-manifest.json`. The export checksum is verified against the evaluated

original and newly trained exports remain available locally.
